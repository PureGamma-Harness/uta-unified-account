# 分片容量实验：Draft 交付与否决结论

本 PR 叠加 M1 分支，是单主机账户分片和持久全局屏障的受限工程实验。**生产、HA、跨分片结算和持续万笔容量全部未通过**。它不替代 P1，也没有将 router 暴露为新的公网交易服务。

## 候选与完整测试

候选代码 `eb2d58bb7a5a1925d1c2cf8be11af2b89754b4ca`，包含当前 main 的原研究功能、M1 全链路及分片修复。**428 项测试通过，0 failures/errors/skips，27.57 秒**。其中包含 12 项分片模块、10 项独立故障及 3 项控制库权威隔离测试。

账户用固定 SHA-256 映射到唯一分片；layout、精度和 policy hash 不得在线变更。所有业务写需经过 router；共享本机 flock 保护准入，独占锁保护行情发布/暂停。一个账户的现金、债务和全部仓位仍在同一个本地事务内。事件游标明确为 `{shard, sequence}`，没有伪造跨片全局序列。

## 已修复的实际失败

独立组在早期候选复现：旧 control 恢复后同一资金凭证可重复注资另一片、运行中换片可误写、缺片会建空库，以及检测行情屏障不一致后仍保留 active flag。修复后，每个事务校验片号/layout/初始化封印，资金写前和启动时核对全局 claim 与本地回执，发现问题持久暂停。控制库、交易库和研究库类型也互斥，误开不新增账户/分录/表。

global claim 与片内入账不是跨库原子提交。允许的中间态是“claim 已提交，本地尚未提交”，永久绑定原片和原命令，可重试完成一次。反向“本地已入账但 claim 缺失或不同”必须停机对账，不能自动猜测或释放凭证。

故障回归包含真实 `os._exit` 和双进程锁竞争。所有已确认的上述缺陷在当前候选关闭，独立组同意继续 **Draft** 工程审查，同时否决生产启用。

## 恢复与回滚

先全局暂停、等待在途准入完成、停止所有合作写者，再备份控制库和全部分片及 WAL。恢复到新的私有目录，验证 layout、全部分片身份和资金 claims/回执，逐片重放；未完成外部已确认命令对账前保持暂停。不能仅恢复旧 control、换片、删缺片后建空库或在线更改 shard count。

移除实验时停机并保留原 layout/全部数据库，禁止用 M1 单库服务打开任一 control 或绕过 router 同时接单。转回单库需要经独立验证的新迁移流程；当前不自动合库，不执行跨片转账。

同主机 flock 不是多节点 lease/fencing，FULL COMMIT 不是跨 AZ 复制确认。尚无跨片撮合两侧义务、全局共享信用池、在线 resharding、30 分钟真实清算压力、长稳/热点/混合负载或正式 RPO/RTO。后续应先设计批提交、账户队列和跨片结算协议，并维持独立正确性验收，再做容量提升；不得仅把更多数据库当成生产高可用。
