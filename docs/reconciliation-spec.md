# 逐笔对账与独立仓位重放

`reconcile_exchange(exchange, matching_only=True)` 在一个 `BEGIN IMMEDIATE` 一致事务中读取账本、订单、成交、撮合回执、源账户交接回执、负债投影及事件。此检查只读，不创建表、不补保护触发器、不修改状态，也不打开嵌套写事务。任何检查失败都阻断验收；不能把缺失证据当作空仓或零负债。

## 对账顺序与独立公式

1. 重放逐币种双分录，核对哈希链、序列和物化余额。
2. 检查经典账户导入与补偿交还回执的 SHA-256、业务身份、请求摘要及原分录。仅未交还的有效导入可作为仓位创世状态；已交还的导入不继续贡献仓位。源写入者失效、外部托管资金和快照增量完整性仍需外部证据，检查通过不代表已经验证这些事项。
3. 按已提交 `FILL_APPLIED` 事件序列独立重放每个账户、每个品种。每条成交必须有且仅有一条对应事件，事件金额、价格、已实现损益、费用和当时累计订单状态必须一致。
4. 对每张订单，成交有符号数量总和必须等于 `filled_quantity`，不能超量或反向；OPEN、PARTIALLY_FILLED、FILLED、CANCELLED 状态与数量一致。累计名义金额、`fee_notional` 和 `charged_fee` 逐项核对。
5. 将独立计算的仓位数量和有符号成本与 `uta_positions` 精确比较。没有成交或有效源创世记录的外部仓位直接拒绝，不能假设它从零生成。
6. 在同一事务中核对撮合回执、双方订单与成交、资金分录和撮合审计事件。严格模式要求每条成交归属实际双侧撮合；成交增量按品种合计为零。
7. 调用借贷模块的只读校验，逐账户、逐币种比较本金和利息投影与各自负债账本科目。未初始化借贷模块时，仍直接比较导入的负债与账本，不能跳过源债务。

重放使用本模块自己的 `Fraction` 算术与显式 USD 最小单位取整，**不调用**生产 `ExchangeService._project_fill`、费用函数或成本转换函数。测试将生产计算函数替换为抛异常的函数后，对账仍应成功。

独立成本规则以仓位数量 `q`、有符号成本 `C`、本次成交 `d`、成交价 `p` 表示：

- 同向加仓：`q' = q + d`，`C' = C + d*p`，实现损益为零。
- 反向成交：先计算平仓数量 `min(abs(q), abs(d))`，按原仓位比例分摊有符号成本；买入平空或卖出平多产生的准确现金流减去该成本，得到准确损益。
- 实现损益按 USD 最小单位向负无穷取整。部分平仓的取整尾差保留在剩余有符号成本中；全平或反转时，不足一个最小单位的有利尾差归系统。
- 反转后的新开仓成本仅为反转剩余数量乘本次价格。
- 同一订单累计费用为 `ceil(累计实际成交名义金额 * 固定费率)`，本次费用为新累计费用减去已经收取费用。向上取整只作用于累计金额，不能因拆成微小部分成交重复收取一个最小单位。

这些是本系统的明确政策，不声称复刻任何交易所。账户本金和利息保持原始毛额；对账不能先净额化来掩盖抵押折扣差异。

## 使用与故障处理

```python
from uta.reconciliation import reconcile_exchange

report = reconcile_exchange(exchange)  # 默认要求全部成交来自真实双侧撮合
```

输出含账户、订单、成交、仓位、有效导入、撮合、逐笔分录和非零负债计数。`matching_only=False` 只用于明确检查旧版手工授权成交的数据库，输出会保留 `unpaired_fills`，不能把这种检查标作双侧撮合验收。

服务正常启动或备份恢复后，使用与数据库策略一致的软件版本执行本检查并保存提交 SHA、备份摘要和 JSON 结果。失败时保持新增风险暂停，保留原数据库/WAL/日志，通过业务 ID 定位差异；不得直接 UPDATE 仓位或删除确认成交来“修平”。纠错应通过授权补偿交易与可追溯分录，并重新对账。

本模块不迁移业务 schema；回滚代码时保留全部原始记录与回执。对账是线性历史重放加账本验证，目前不是在线低延迟风控路径；历史数据规模、重放耗时和内存容量需要单独测量。

## 验证门槛

`tests/test_reconciliation.py` 验证仓位数量与成本被改、订单累计量与费用元数据被改、手工成交、未知仓位来源、导入仓位平仓反转、导入交还、负债投影被改、回执校验和、低 Decimal 精度及重启恢复。跟踪 SQL 的测试要求全程只有一个一致事务，且没有 INSERT/UPDATE/DELETE/CREATE。

撮合专用检查 `Matcher.verify` 保留为回执与双方执行的组件检查。完整四侧验收必须使用本模块，不能只用撮合回执存在就推断仓位数量或成本正确。
