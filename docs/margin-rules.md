# 第一批 Cross 与借贷规则

规则 ID：`UTA-CROSS-LOAN-v1`。这是本项目明确选择的保守政策，不复刻 Bybit、Binance 或其他交易所。实现位于 `uta/portfolio.py`；人工复算用例在 `tests/test_portfolio.py`。所有配置有独立规则版本，输出同时携带规则、产品目录和行情版本及行情观察时间。

金融规则负责人：**待指定、未签字**。独立验证负责人：**待指定、未签字**。自动测试通过不等于真实人员签字、交易所公式对齐或生产验收。第一批以后的产品和账户模式不能通过修改配置来开启。

## 资产、负债与冻结

`gross_assets` 是持有的非负总资产，借款本金 `principal` 和应计利息 `interest` 分别保存，不能先与同币资产净额化。`frozen_assets` 表示待出账而暂不能重复作抵押的数量，必须小于等于持有总额；它不是已经完成的出账。订单保证金 `order_margin` 是另一项占用。调用方不能把同一冻结同时填入两个字段而不说明重复保留的原因。

`CollateralTier.up_to` 是累计 **USD 市值** 上界，按边际分段计算。档位因素必须随市值增加而不增加，最后一档无上界。例如前 100 USD 的因素为 0.8、剩余为 0.5，150 USD 的折扣抵押值是 `100×0.8+50×0.5=105`，不是 `150×0.5`。`loan_to_value` 在折扣抵押值之上限制借款；它与风险抵押折扣用途不同，均明确列出。

以下数值全部以 USD 报告，`A` 为总资产、`F` 为冻结资产、`L=本金+利息`、`P` 为价格、`H` 为上述分段折扣函数：

- 账面权益：`accounting_equity = Σ(A×P) − Σ(L×P) + 未实现盈亏`。
- 抵押值：`collateral_value = Σ H((A−F)×P)`。
- 风险权益：`risk_equity = collateral_value − Σ(L×P) + 未实现盈亏`。
- 可贷款抵押值：`loan_value = Σ[H((A−F)×P) × loan_to_value]`。
- 冻结市值单独报告：`frozen_value = Σ(F×P)`；尚未出账的资产仍计入账面权益。

折扣只作用于资产。负债始终按全额价格扣减，应计利息也计入负债及借款保证金。第一批 USD 同时是固定报告与结算单位，价格和抵押因素必须为 1；USD 抵押档位也必须为 1。其他抵押币可有折扣。稳定币脱锚只能用于 USD 之外的抵押币压力情景；结算币本身脱锚需要后续版本。

## 独立 IM、MM 与可借数量

借款保证金是本项目的显式附加要求：`借款IM = Σ(L×P×借款IM率)`，MM 使用各自的 MM 率。线性合约 `PNL = 数量×乘数×mark − 有符号cost_basis`；IM/MM 分别为绝对标记名义金额乘对应风险档位率。`cost_basis` 已包含合约乘数；不能把经过展示精度舍入的平均开仓价重新当作权威成本。

`IM = 借款IM + 线性IM`；`MM = 借款MM + 线性MM`；`available_margin = risk_equity − IM − order_margin`。独立版本的 `PortfolioRules.linear_margin` 是此计算器的保证金率来源，行情中的参考 IM/MM 不会覆盖它。接入服务时必须统一有效参数版本，不能让下单与借贷分别使用不同的一套费率或保证金率。

可借报价保守地假设借款所得立即移出抵押池，不把借入所得再次抵押来提高额度。对币种 `j`，先计算以下上界的最小非负值，然后按借款 `quantity_step` **向下**取整：

1. 该币本金限额减去已有本金。
2. `(账户总负债上限 − 当前总负债USD) / Pj`。
3. `(loan_value − 当前总负债USD) / Pj`。
4. `available_margin / [Pj × (1 + 借款IM率j)]`。

借款后还必须满足严格的 `风险权益 > MM`。若 IM 与 MM 相等导致额度上界恰好等于 MM 门槛，再少一个数量步长。`MM=0` 时也不能把权益为零或负数的账户判断为安全。IM 可用保证金等于零允许边界成立，MM 等于权益触发 `LIQUIDATION`。这些状态是参考风险状态，不会自动替代服务的清算事务。

多个币种的报价共享同一个抵押池，**不能相加执行**。真实借款、提现或下单必须在持久化事务中重新计算并原子提交；独立计算器本身没有授权或修改余额的副作用。

## 人工复算证据

合成账户持有 USD 1000、BTC 2；BTC 报价 100，冻结 0.5。BTC 前 100 USD 折扣为 0.8、之后为 0.5，贷款 LTV 为 0.5；USD LTV 为 0.8。本金 USD 100、BTC 0.1；利息 USD 1、BTC 0.01。持有 2 份乘数为 2 的线性合约，mark 110，有符号成本 400。

独立手算：可抵押 BTC 值 `100×.8+50×.5=105`；总抵押值 1105；本金 110、利息 2、总负债 112；合约 PNL `2×2×110−400=40`。因此账面权益 1128、风险权益 1033、loan value 852.5。若 USD 借款 IM/MM 为 .1/.05，BTC 为 .2/.1，线性为 .1/.05，则 IM 为 56.3、MM 为 28.15；订单占用 10 时可用保证金 966.7。账户总债务上限 500 时，单独报价 USD 最多 388、BTC 最多 3.88。

测试文件直接使用上述人工数字，不调用生产计算器来生成预期值；另外验证同币资产与负债不先净额化、零 MM、负权益、缺报价、低 Decimal 精度和冻结边界。

## 压力参考计算与 PM 门槛

`scenario_reference` 只支持显式 spot/depeg 与线性价格冲击。风险单元区分 underlying、产品类型、expiry、settlement 和 symbol；同一 underlying 不授予抵消，第一批拒绝任何 `eligible_hedges` 配置。每个单元损失取非负值后相加，不允许另一个单元的收益抵消该损失。输出最坏场景、逐场景与逐风险单元损失。

参考要求为 `max(最坏场景损失, minimum_floor) + liquidity_addon + credit_addon`。floor 不与相同场景损失重复相加；两个 addon 明确单列，调用方必须解释和校准其来源。这不是正式的 PM IM/MM 聚合。`pm_activatable` 固定为 false，不能通过构造参数覆盖。

期权波动率及期限结构、逆向合约重估、相关性校准、结算币风险、完整流动性模型、保险基金和 ADL 尚未验证，也没有生产准入权限。PM 需要后续产品重估、独立验证和真实负责人的签字，不能用这份压力参考结果开启。

## 精度和输入规则

配置及财务输入只接受有限 `Decimal`，JSON 财务值必须是十进制字符串。内部加减乘除使用精确 `Fraction`，不依赖调用方 Decimal 的精度、舍入模式或 Inexact/Rounded traps。计算结果不隐式货币舍入；借款额度唯一有方向的舍入为按数量步长向下取整。真实结算的币种精度和不利方向舍入由持久化交易服务负责，不能在展示层替代。

缺少价格、借款限额、抵押规则、风险档位，过期行情、未知产品和未支持模式均报错；不会把无法计算的风险当作零。
