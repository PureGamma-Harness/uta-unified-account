# 多工作组交付与审批台账

本轮工程从 `main@30deff6` 开始，根 agent 负责集成，独立 worktree 和功能提交保留各组实现与审查历史。环境最多同时运行 7 个 agent（含集成负责人），以分批交接扩展了 11 个子 agent 的独立分工；这不是多机运行能力或生产人员编制。

| 工作组 | 工程任务 | 交叉审查 |
| --- | --- | --- |
| 账户与账务 | storage：持久账本、借贷；migration：经典导入与补偿回退 | fault_acceptance、matching 的全量对账、root |
| 量化风险 | market：产品目录、Cross、阶梯抵押、场景参考和交易门禁 | review：独立二分借款参考与压力重估；root |
| 交易与清算 | trading：接纳、预占、监督器；matching：真实双侧结算；spot：现货资产锁与两币结算 | review、fault_acceptance |
| 分布式与性能 | operations：开放环原始基准、部署恢复；storage_performance：同口径 profile 与连接实验 | root、fault_acceptance |
| API 与运营 | gateway：认证分权、私有事件和契约；root：集成命令与运行循环 | review 的真实 HTTP 集成、operations 的真实 SIGTERM 测试 |
| 独立验证 | review、fault_acceptance：参考计算、并发、崩溃、真实 SQLite FULL、形式化反例 | 集成门槛拥有否决权，不以实现组自测代替 |

## M0：证据、持久基础与工程安全

交付：差距、目标架构、追溯矩阵与版本资料；精确持久账本；受控行情；分权 API；安装包、备份恢复；并发与故障测试；profile 和原始开放环结果。验收仅覆盖已测试的单机故障模型。可运行代码及手册随各组 commit 提交，PR 保留完整测试证据。

## M1：首批合成纵向链路

交付：明确限制的经典账户导入、gross 现货借贷、多币种抵押、现货锁/撮合、线性限价撮合、部分清算、重启和逐笔对账。只有实际对手订单才能产生撮合成交。未获授权的源系统、稳定币真实结算和未实现的在途切换不能由合成链路证明。

启用边界：Cross、单一合成 USD 结算、显式借币、限价和累计只减仓。未支持的条件单、自动借币、改单、市价、多腿、模式转换与外部托管出金必须拒绝。无流动性保持待成交和残余风险，不填造清算成功。

## P1：首批生产门槛

必须关闭 [G0–G7](acceptance-gates.md)：正式首个稳定币产品/资金交接、源快照加连续事件与旧写入者失效验证、实际撮合全链路、独立金融校准、每秒万条持久接纳及万笔唯一清算成交持续 30 分钟、混合热点/脱锚/深度下降、长稳、复制和容灾、真实责任人签字。

状态：**BLOCKED**。没有签字、没有 30 分钟容量、没有跨可用区故障保证时，工程里程碑通过不能改写此状态。

## P2 / P3

P2 增加多结算、交割、反向的独立估值、PnL、结算币风险、资金费和到期处理。P3 增加期权全量情景重估、波动率曲面、期限/基差/相关性破裂、合资格 spot 对冲和受限跨组抵消。两批都须重复正确性、性能、故障及金融签核；参考场景函数的存在不授予交易能力。

## 生产签核

当前真实金融规则负责人、SRE 容灾负责人、独立模型审批人和真实资金上线批准人均待指定。工程 agent 的发现、提交和测试可以审查，不能代替真实授权人员签字。不得为了交付状态填写虚构审批记录。
