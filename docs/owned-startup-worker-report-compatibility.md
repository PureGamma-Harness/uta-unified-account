# Strict worker-report compatibility v1: CODE-only preparation

The validation producer's reviewed6303 version always adds two optional v1
diagnostic report fields. The old managed-variant qualification grammar accepted
exactly seven worker keys and therefore rejected even empty new diagnostics.
This adapter changes only that schema boundary in `qualification`; it does
not change producer bytes, financial fencing, data, old evidence or an approval.

Accepted worker grammars are exact legacy7 keys, or exact new9 keys: legacy7
plus both `lease_observations` and `lease_observations_truncated`. New records
require `type(lease_observations) is list`, exactly `[]`, and truncation `is False`.
Any other key count/content, half pair, nonempty list, truncation, tuple,
list subclass,0 orNone rejects. Successful QA is not permitted to hide a
diagnostic failure or truncated collection. A complete new worker requires the
two summary keys; the existing all-worker-key type and value comparison then
applies to all nine. Reports are not projected or rewritten.

The original five literal-success flags, native zero counts/exit, test count,
full-run command, source-before/after manifest, interpreter identity, exact
local commit, push/PR source/job/status, raw log/digest and package/installed/
negative-omission checks stay unchanged. Old reports still cannot certify new
source. No M05/spent registration, D2 flag, original PENDING record or old
code-bound-authority marker changes. This grammar accepts evidence shape; it
does not authorize execution or funds.

`worker_compat_fake.py` proposes six methods/32 examples. It compiles actual
`GateError`, `require` and the unchanged actual qualification function's QA
prefix, stopping explicitly before `package=q['package']`. Every accepted
example passes three local and eight CI records with fake source/runtime/log
proofs. It does not import the tool or execute its entrypoint, package,
installed, omission, resource, cohost, process or financial paths. Proof
regular-file/JSON/hash loading and Path/log/provider data are declared memory
boundaries. Type-alias injections are stronger fake objects than ordinary JSON
decoding produces; they test the strict native-type branch only.

Expected accept/reject results and exact messages are hand-recorded independent
policy examples in `worker-compat-reference.json`, not generated by production
helpers. Four positive examples cover old/new/mixed matrices;28 negatives cover
unknown/half fields, wrong summary/collection/booleans, all original zero-count
categories and bool aliases, source/runtime binding, pending/old CI and raw log
rejection. Original fake proof objects must remain unchanged after each call.
The actual full package qualification is never declared passing by this fixture.
