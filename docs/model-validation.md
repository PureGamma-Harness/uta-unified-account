# 模型独立验证记录

**生产模型验收：BLOCKED。** 本记录由与模型实现分开的验证 agent 编写，证明选定项目规则在合成数据上的软件一致性。它不代表真实金融规则负责人、独立量化负责人或交易所签字，也没有校准任何真实产品的风险参数。

## 对象、版本与独立性

验证对象是 [第一批 Cross 与借贷规则](margin-rules.md) 的 `UTA-CROSS-LOAN-v1`、[产品能力门禁](product-support.md)，以及不可激活 PM 的压力参考计算。第一轮源代码基线为 `0bdf9b3`；验证代码位于 [test_portfolio_reference.py](../tests/test_portfolio_reference.py)。规则、目录及行情版本均单独检查，不能用行情里的参考 IM/MM 覆盖显式规则版本。

参考计算器只调用生产模型的公共入口 `calculate_cross_risk`、`scenario_reference` 取得待比较结果。预期值不调用生产抵押折扣、额度、风险、压力重估或十进制转换 helper，也不把生产输出反灌为预期值：

- 抵押参考按累计区间的交集宽度积分，分别计算 gross 资产、冻结资产、边际折扣和贷款 LTV；负债本金、利息按全价扣除。
- 线性持仓逐笔按数量、产品乘数、标记价和有符号成本重估；借款和线性风险分别计算 IM/MM。
- 借款参考在币种数量网格上做整数二分搜索。每个候选数量都重新检查借款后的本金上限、总负债、贷款抵押值、可用 IM 和严格 MM 不等式，而不是照抄生产实现的最小额度上界公式。
- 压力参考分别重估每个资产及每个线性风险单元的情景前后价值，再把该单元损失截断到非负。其他单元的收益不融资该损失。最终只计算 `max(最坏损失, floor) + liquidity_addon + credit_addon`。

所有比较使用精确 `Fraction`，财务金额与币种原生借款数量要求完全相等，没有允许数值误差。输入是有限 `Decimal`，测试还在低精度、向上舍入、小指数范围及 `Inexact` / `Rounded` traps 条件下重复计算。

## 已运行的合成验证

复现命令：

```sh
python -m unittest discover -s tests -p test_portfolio_reference.py -v
```

Python 3.12.14 环境下第一轮 9 项测试通过，包含下列生成样本；样本数量不是独立金融证据数量。

| 检查 | 输入及判定 |
| --- | --- |
| 人工用例 | USD 1000、BTC 2、BTC 冻结 .5、USD/BTC 本金及利息、乘数 2 的线性仓位；逐项核对规则文档中的权益 1128、风险权益 1033、IM 56.3、MM 28.15、可用 966.7、USD 可借 388、BTC 可借 3.88 |
| 随机 Cross 对照 | 种子 `931472` 的 320 个账户，包含不同价格、三档抵押曲线、LTV、同币总资产及负债、利息、冻结、正负仓位、不同乘数、借款步长及本金/总负债上限 |
| 状态及正额度覆盖 | 上述样本包含 HEALTHY 175、LIQUIDATION 127、MARGIN_CALL 18；71 个样本至少有一种正的可借数量 |
| 精确边界 | 第一档市值上界前、等于、后；全额冻结；权益等于 MM；零 MM 和零/负权益；IM/MM 相等时数量网格严格少一格；同币债务不在折扣前净额化 |
| Decimal 隔离 | 对固定种子的前 32 个账户，在精度 1、ROUND_UP、Emax 2、Emin -2 且开启 Inexact/Rounded traps 下比较公共入口和独立参考 |
| 压力对照 | 种子 `792416` 的 96 个账户，每个 4 个情景，共 384 个情景；包含价格归零、上涨、下跌、档位穿越、正负线性风险单元和 floor/addon |
| 抵消与能力门禁 | 同 underlying 的相反持仓和现货不跨风险单元抵消；明确拒绝 Isolated、PM、期权、逆向合约及 USD 报告单位脱锚；`pm_activatable` 固定为 false |
| 缺失输入 | 缺资产或合约报价、缺抵押/借款/保证金规则、过期行情均失败，不补零或默认为健康 |

测试样本包括合法但偿付不足的账户，用于验证风险识别，不能理解为允许这些账户生产准入。可借报价是每币单独的保守报价，多个币种共享抵押池，不能相加执行。模型不执行资金变动。
