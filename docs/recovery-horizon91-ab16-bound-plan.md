# Bound successor: actual-worker identity and original cleanup semantics

This new static proposal supersedes 7ce60c197a79f25dac887f352d35749386b812f9.
It preserves that proposal's files, earlier 8f and 81 helpers, the b570 sole actual
NO_REPRO/incomplete observation, and independent original red vectors unchanged.
No new native case has run. Root and independent exact-byte GO remain required.

The registered plan is now
`evidence/runs/recovery-horizon91/runtime-ab16-bound-preregistration.json`;
the controller is `run_runtime_ab16_bound.py`, and its original-case helper is
`trace_original91_bound.py`. This uses the fixed ABBA16, ordinary assertion FAIL
continue / any ERROR or technical uncertainty stop policy, same actual A/B paths,
source91, 27-second worker / whole30 budgets and original 5/5/5/5/15 windows
specified in the prior final-plan document. Those original limits are unchanged.
The old proposal is not the execution target. All sixteen fixed slots and all
raw outcomes, including explicit NOT_RUN after a safety stop, are retained.

Three pure contracts are bound. `strict_result_contract.py` closes the original
JSON issue with exact booleans, non-bool integer counts, one actual unskipped
case, matching was_successful/case_passed/failure/error/historical-stage facts,
and matching observer item/aggregate facts. The independent four original red
vectors and subsequent result vectors remain separate evidence.

`strict_runtime_contract.py` requires the **actual case worker** to report the
exact expected Python tuple, sys.version first token, resolved executable,
SQLite version, optimization/bytecode settings, CPU2, controlled environment,
and mapped libpython paths/hashes. The new helper records this in both
original_case_start and its final case_result. The controller requires both
actual observations to match one another and the approved binding. Preflight
identity alone cannot grant actual worker identity. Runtime provider archive,
executable and pinned library hashes are checked again after the case; a missing
file or changed hash stops the batch. The no-SQL preflight still captures host,
compiler/libc, flags and mapped dependencies in its actual scoped environment.
A clears LD_LIBRARY_PATH; B alone sets its prefix library. No global runtime or
other job is changed. Same Python version does not mean the failed CI build.

`strict_event_contract.py` parses original events rather than trusting their
hash or worker aggregate. It requires original spawn accounting and distinct
PID/birth records, final real pidfd exits, original status-call pairing, explicit
observer start/end/postjoin observations, and consistency with result flags.
Every kill must be an original uta-process-supervisor kill with a preceding
original native observed lease for that PID, active=false and expired by its
actual native now_ns. **Any MainThread kill, including router.close fallback,
or any unclassified/incomplete kill stops the batch**, even if the testcase's
cleanup_forced_kill observation stayed false. Fixture and external forced-cleanup
flags remain separately mandatory. A successful original case also needs its
original financial assertions and actual two publication CID receipts in events;
no extra SQL query is introduced. A held PENDING command is not financial acceptance.

The controller performs its own literal-boolean gates, event/actual-unittest
consistency, source266 maps, and read-only new-session cleanup checks. A bare SID
is never signal authority after possible leader reuse. Only retained launcher
pidfds and original logged child births can authorize exact pidfd cleanup;
unbound residuals are preserved and escalated to root without a guessed signal.
Any forced signal or unknown cleanup still makes the sample and whole batch
technical NO_GO. Remaining slots are not retried. The last 0.75 seconds of each
whole30 sample is reserved for bounded final cleanup/evidence; expiry is technical
NO_GO and never widens an original recovery assertion.

After exact root GO, the invocation uses outer umask077, clears PYTHONPATH,
PYTHONHOME, LD_LIBRARY_PATH and LD_PRELOAD, sets PYTHONDONTWRITEBYTECODE=1, and runs
`/usr/bin/python3.13 -B evidence/runs/recovery-horizon91/run_runtime_ab16_bound.py
--run NEW_PRIVATE_OUTPUT`. It has no default action. Root must bind the exact
controller, helper, all contracts, probe and new registration hashes before
launch. This document and registration authorize no execution by themselves.

The experiment is diagnosis only. All PASS means NO_REPRO, not a fix, source91
qualification or production approval. A failure is retained by original stage;
no version-only or unique historical cause is assumed. No schema, production
runtime/default or global deployment is changed; rollback is to stop using this
optional experiment while retaining every old and new evidence artifact.
