# 持久命令、单写者与恢复的独立验证

独立验证组只使用合成资金、账户、行情与故障。本报告区分参考账本、研究 Store、持久交易服务与独立进程协议的证据。参考模型通过不等于持久金融实现通过，排队成功也不等于订单已接纳。生产、真实资金、复制/HA与正式容量关卡继续 **BLOCKED**。

## 阶段一：独立发现并关闭宽精度回放缺口

以 `ad3f5b8` 为基线，本组实际复现：`Ledger({'USD':18}, unit_digits=60)` 可以记入金额 `10000000000000000000000000.123456789012345678`，而 `Ledger.replay` 强制恢复为默认38位，因而拒绝这份合法日志；接口还不允许调用方传回原 `unit_digits`。这是内存研究账本的恢复参数缺口，不是持久交易账本范围已被扩大。

修复来自远端 `fix/ledger-replay-precision` 的 `a85567a`，集成负责人只挑选四文件的小补丁为 `2bddc9a`，没有合并旧分支快照。回放现在接受显式保留的原精度，默认38位和构造器范围校验继续保留。历史金额不能自动放宽恢复政策。

`tests/test_durable_reference.py` 的独立回归不调用生产换算或风险函数生成预期，按整数最小单位及 `Fraction` 核对：

- 原精度38/40/60、USD精度18，接近各自上限的资金、1个最小单位付款和精确余额。
- `prec=1`、Emax/Emin=±2、Inexact/Rounded traps 下回放、原ID重试及随后越界记账拒绝；拒绝不改变分录与余额。
- 默认精度仍拒绝宽历史，非法显式精度仍由原构造器拒绝。

基线原始测试产生9个子案例 TypeError（缺 `unit_digits` 参数），默认拒绝宽历史的测试通过；没有跳过失败或改金融预期。应用 `2bddc9a` 后，本阶段三个精度测试及下述模型回归 **4项全过、0 failures/errors/skips，0.014秒**，Python3.12.14。最终金融与进程候选就绪后再补全本文件的实际验收记录，不能把这4项小范围结果冒称完整持久命令验收。

## 研究 Store 提交失败分支的只读审查

只审查了 `ad3f5b8` 之外真正新增的提交 `origin/test/store-commit-recovery@c57176b`。该分支与基线共同祖先为旧 `02549e5`，因此不能用两端完整快照差异恢复旧文件。实际补丁仅新增 `tests/test_store_commit.py` 和两处文档更新，没有运行时修改。

三个新案例在真实 SQLite 建立 `DEFERRABLE INITIALLY DEFERRED` 外键；触发器先成功写入，最后由真实 COMMIT 失败。trace 回调只观察真实SQL，不伪造 COMMIT 异常或金融成功。分别验证单命令、同库多账户批次、独立分片部分成功后原ID恢复；成功分片的 transition 不得再次执行。独立组通过 `git show` 在内存载入该测试源码，在当前基线实际执行 **3/3通过、0跳过，0.112秒**，没有引入分支文件或覆盖当前文档。

未发现测试质量上的挑选阻断。建议只引入新增测试文件，并围绕当前版本更新说明。它们验证 `uta.store` 的研究快照与回执协议，不等同于 `ExchangeService` 交易账本、持久inbox、fencing或撮合验收；持久路径需要各自独立故障证据。

## 独立有界命令模型

```sh
python formal/explore_durable_commands.py
python -m unittest discover -s tests -p test_durable_reference.py -v
```

模型不导入任何生产模块。边界为两个账户、四个不可变命令ID、两个写者generation、一个原子数据库写事务。账户容量用整数；命令包括接纳、容量拒绝和撤单。遍历持久排队、按账户先后执行、提交前进程退出、租约过期/接管、终态与金融同提交以及延后投递/查询。已排队记录、金融数据和终态的持久性是模型假设，不是它证明的物理性质。

安全模型实际遍历 **817个可达状态、2372条转换**，没有容量重复占用、同命令重复影响、金融状态缺少成功终态、提前发布接纳或失效写者提交。四个独立负控制必须各自产生带动作和状态的反例，否则脚本失败：

| 删除的约束 | 首个反例长度 | 检测的违反 |
| --- | ---: | --- |
| 提交前不得发布接纳 | 4 | 客户收到成功而终态仍为PENDING |
| 金融与终态须同提交 | 4 | 已改变预占但没有成功终态 |
| 原ID重试不得重做影响 | 5 | 同命令产生第二次金融影响 |
| COMMIT须有当前有效写者 | 5 | 已过期或已被接管的写者提交 |

模型不证明实现与抽象等价、任意规模、队列活性/公平性、真实时钟正确、SQLite落盘硬件、跨主机复制或HA。它的成功不能代替独立实际SQL、PID与金融回归。持久inbox与fencing实现尚在接线时，本报告不提前填写通过结论。
