本次：AMD EPYC 9V74，5 个可见且可绑定逻辑 CPU，cgroup `cpu.max=400000 100000`（4 CPU 配额）、16 GiB 内存上限，Linux x86-64，Python 3.12.14，SQLite 3.53.1，工作区 overlay 文件系统。SQLite 临时库位于独立工作区，通过原脚本的 `--db-dir .` 指定，未放到内存文件系统；WAL/FULL 行为沿用原源码。

已发布结果注明 Intel Xeon Platinum 8573C、9 个可见逻辑 CPU。本次硬件和 CPU 配额与其不同，因此复现的是**同一代码、数据规模、计时和正确性口径**，不要求吞吐数值相同，也不将数值差异宣称为代码优化收益。八进程计算在本次环境超过 CPU 配额，尾延迟可能受调度影响。

环境、运行模块及脚本的 SHA-256、每条命令起止时间、完整 stdout/stderr 与返回码保存在 [复跑证据目录](../evidence/main-baseline-20261114/)。`manifest.json` 为所有证据文件提供哈希和字节数；`environment.json` 记录原样执行的基线 SHA。原脚本输出的是聚合统计，**没有逐请求原始时间、P99.9 或持久数据库快照**；临时数据库由原脚本在运行后删除。不要把本次保留的完整 stdout 称为逐请求 raw。

### 计划到达突发

原样复跑 `--target-rate 10000 --accounts-per-worker 100 --workers 4 --max-pending 8`：400 个计划到达，42 户完成及 42 笔模拟清算成交，358 个过载拒绝，未完成账户为 358。每个 worker 等待队列上界仍为 8。完成账户从计划到达计算的 P99 为 217.849ms；实际计时 0.249979 秒，完成率 168.01 户/秒。

该场景只有 40ms 的计划到达窗口，不是持续 10,000 笔/秒；过载拒绝不计作完成。其余五条命令默认是 closed-loop：每进程完成一项才执行下一项。不能拿默认 closed-loop 结果宣称开放环容量达标。原发布突发完成 40 户，本次 42 户是依赖调度和执行速度的差异，不是预期业务计数漂移。

## 复跑命令

在隔离目录检出确切基线，避免将集成后的新模块版本混入历史结果：

```sh
git worktree add --detach /tmp/uta-published-baseline f8d72efaac69353113740d34d7ae5c39e3828c7a
cd /tmp/uta-published-baseline
python scripts/benchmark_pm.py --mode compute --workers 8 --checks-per-worker 20000
python scripts/benchmark_pm.py --mode all --workers 4 --checks-per-worker 3000 --accounts-per-worker 80 --db-dir .
python scripts/benchmark_pm.py --mode durable --workers 4 --shards 1 --accounts-per-worker 80 --db-dir .
python scripts/benchmark_pm.py --mode durable --workers 4 --accounts-per-worker 100 --db-dir . --target-rate 10000 --max-pending 8
python scripts/benchmark_pm.py --mode batch --workers 4 --accounts-per-worker 80 --batch-size 32 --db-dir .
python scripts/benchmark_pm.py --mode batch --fused --workers 4 --shards 4 --accounts-per-worker 80 --batch-size 32 --db-dir .
```

本次未缩小已发布规模或降低计数阈值。每次 `*.invocation.json` 同时保留整个进程的耗时；原 benchmark 内部计时排除部分准备、进程启动和最终重开核对，这两个时间不能混写。全部模拟账户和资金都是公开源码构造的合成数据。

## 已关闭与仍阻断的验收项

已关闭：已发布材料可以定位；原始版本、六条命令及完整规模可执行；三项指定基线的业务计数复现；脚本的版本连续、分录平衡、只减仓和重开核对检查未报告错误。

仍阻断：这些清算成交由模拟器按合成行情生成，没有独立盘口、真实双侧撮合或网络确认；本次没有 30 分钟持续测试、长稳、混合负载、P99.9、跨可用区复制、旧主 fencing 或真实资金审批。纯计算超过万次每秒不等于万笔持久接纳；431.17 笔模拟成交每秒也不能代替万笔真实撮合清算验收。集成新交易链路后必须重新跑其自身的明确口径，不能引用本报告作为新实现的容量结果。
