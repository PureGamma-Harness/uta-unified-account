# 分批验收与上线否决门槛

本文件定义验收政策，不是已通过证明。结果必须附运行 commit、命令、环境、原始输出与独立审查。Agent 审查不替代真实金融规则负责人与上线审批人。

| 关卡 | 必需证据 | 当前结论 |
| --- | --- | --- |
| G0 参考正确性 | 现有黄金案例、独立计算、低精度/边界/回放全部通过 | 以对应 commit 的 unittest 原始输出为准 |
| G1 单节点事务 | 并发不超占、命令幂等、逐币平衡、磁盘满/忙/崩溃不返回假成功 | 工程测试范围；不推广到多节点 |
| G2 首批纵向链路 | 经典导入→现货借贷→真实双侧撮合→结算→触发/部分清算→重启→订单/撮合/仓位/分录四侧核对 | 合成链路，逐组件证据；真实迁移与产品审批仍阻断 |
| G3 订单万笔 | 开放环 ≥1800s，≥10,000 条/秒唯一持久接纳和预占，合理拒绝比例另报 | **BLOCKED，未以短测/拒绝数替代** |
| G4 清算万笔 | ≥1800s，足够实际流动性，≥10,000 笔/秒唯一撮合确认+仓位+资金分录全部提交 | **BLOCKED，模拟动作/按标记价成交不算** |
| G5 混合/长稳 | 热账户、双倍突发、行情/撮合/清算/查询并发、尾延迟、积压清空及全量对账 | **BLOCKED** |
| G6 灾难恢复 | 节点/AZ/跨区域故障模型，复制水位、旧主 fencing、实测 RPO/RTO | 本地进程测试不替代，AZ 级 **BLOCKED** |
| G7 金融与安全审批 | 产品/参数校准、历史/样本外验证、真实责任人签字、权限审查与上线批准 | **BLOCKED，未获真实资金授权** |

只有 G0–G7 全部关闭，才可宣称 P1 对应产品达到生产验收。P2/P3 各自重复相应产品正确性、容量、故障和签核。PM 参考情景或接口字段存在不能作为 PM 启用依据。

## 可复跑功能检查

```sh
python -m unittest discover -s tests -v
python -m uta acceptance
python -m uta demo
python formal/explore_reservation.py
python formal/explore_settlement.py
python -m compileall -q uta tests benchmarks
```

`acceptance` 使用临时合成资金，输出 `production_approved: false`。CI 同时构建 wheel，离开源码目录后再次运行 demo 与 acceptance。原始正式测试结果保存在 `evidence/runs/`；新增测试必须按最终 SHA 重跑，不引用较早测试数量。

## 容量口径

基准分别标识 compute、组件持久接纳、模拟清算和完整撮合。计划到达时刻起算 P50/P95/P99/P99.9，包括队列等待。成功接纳、业务拒绝、技术失败、超时、结果未知、队列满及 late commit 分开报告。重复 ID 只计一次，不把撤单、尝试次数或拆小成交当作新增吞吐。

正式负载记录硬件、CPU quota、内存、磁盘/文件系统、WAL/FULL/复制条件、分片、账户数量、产品、挂单规模、热点及流动性。至少重复三次，结束后重新打开存储，逐笔核对并抽检重放。业务拒绝不能帮助满足持久成功吞吐。100ms P99 若出现在 smoke 工具里，是本系统待审批的临时目标，不是用户已经批准的 SLO。

已知明显低于目标的组件先剖析和优化；不将必然失败的短测包装成 30 分钟验收。分片工具的多个独立 SQLite 文件也不是已实现跨分片账户交易。缺少复制和跨分片结算时，多节点生产门槛保持否决。
