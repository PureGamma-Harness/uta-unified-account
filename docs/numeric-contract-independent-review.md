# 数值契约的独立复核

复核基线为 `4060429`，全部资金和行情均为临时合成数据。本组不修改运行时、不扩大任何
数值范围，也不启动撮合负载。十个标准案例使用预先写下的整数、十进制字面量与 Fraction
结果，生产计算函数只充当被测对象。结论仅覆盖以下边界，不是生产或产品启用审批。

## 输入范围分层

| 层 | 当前实际契约 | 例子及拒绝行为 |
| --- | --- | --- |
| 默认账本及持久账本 | 币种 scale 为整数 0..18；每笔及每科目余额的绝对 minor units 严格小于 `10^38`；Decimal coefficient 最多 38 位、exponent -38..38 | scale18 的最大正额是 `99999999999999999999.999999999999999999`；再加一个原子单位拒绝，流水和业务 ID 不被消耗 |
| 交易、成交及存款入口 | 最多 32 位 coefficient；exponent -8..12；绝对金额不超过 `1e12`，再叠加动作的正数/非零条件 | `1e-8` 可通过形状检查，`1e-9` 拒绝；`1.000000000` 虽等于 1，仍因输入表示超限拒绝 |
| 特权借贷金额 | 使用默认账本的资产 codec，再叠加正数、资金池、账户和资产额度及风险限制 | scale18 的 `1e-18` 可用于已配置、已注资的借贷；同额直接存款目前仍被 8 位入口拒绝 |
| 市场与参考模型 | 最多 80 位 coefficient；exponent 和非零 adjusted exponent 均在 -100..100；正价及参数各有经济范围 | `1e100`、`1e-100` 可表示；相邻越界指数、81 位 coefficient 及非有限数拒绝。这不扩大实际订单价格输入范围 |

这些限制约束输入表示，不仅约束数学值。禁止自动去零、改 exponent 或先舍入再接纳。
纯研究内存账本可显式配置 38..60 位 journal；持久账本和信用 codec 仍使用 38 位默认合同，
研究能力不能推导出持久资金范围已扩大。

原《账务规范》“按资产固定精度转换”的描述并不等于所有入口均支持 18 位金额。上述
分层是现有行为的补充说明；若第一批产品需要 18 位直接入金，必须另行选择版本政策、
修改入口及审计/兼容测试，本组没有把拒绝改成接受。

## 结算与展示

| 用途 | 当前方向 | 手算标准 |
| --- | --- | --- |
| 真实 USD PnL | 按结算币 scale 向负无穷取整 | scale2：`+0.001→0`，`-0.001→-0.01`，`+0.011→0.01`，`-0.011→-0.02` |
| 累计订单费用 | 累计绝对成交名义乘费率后向正无穷取整，再减此前已收金额 | 三笔名义各 1、费率 .0004：累计费用上界均 .01；增量为 .01、0、0，不能逐笔各收 .01 |
| 其他精确金融金额 | Fraction 精确运算，只有分母因子为 2/5 才可无损转十进制 | `1/8→.125`；`1/3` 报 `precision_error(409)`，不能悄悄舍入 |
| margin ratio 展示 | 34 位有效数字、half-even；MM 为零返回 null | 权益 `1+1e-40`、MM1 时，展示 ratio 为 1，实际权益仍严格大于 MM；触发依据必须比较金额 |

PnL 残余由未平仓成本承接。开 3 份、总成本 3，分三次各平 1：按 1.006 平仓的现金
PnL 依次为 0、0、.01，整笔平仓也为 .01；按 .994 平仓依次为 -.01、-.01、0，整笔为
-.02。每组两个客户初始现金各100，最终现金分别同为100.01或99.98，对手 PnL 科目为
-.02或+.04，双方均无剩余仓位。实际本地结算和总账重开校验支持这些预先手算值。

MM0 的 null ratio 不能表示安全；零或负权益原值必须保留。临界相等和风险触发由对应
金额规格决定，不得通过格式化 ratio 判断。这里的 `1e-40` 案例测试参考估值的显示损失，
不宣称 USD2 的现金账本能够保存四十位小数。

测试还把调用方 Decimal 精度设为1、Emax/Emin设为±2，并开启 Inexact/Rounded traps，
验证币种精确借还与结算方向不借用调用方上下文。账本边界只涉及38位十进制整数，所有
案例的值和精度固定且不递增，未做巨大分配或数值资源压力实验。

## 证据和边界

测试定义位于 `tests/test_numeric_contract_reference.py`。首轮 PnL 两个子例只因测试误读
事件字段 `payload.order_id` 而报 KeyError；实际合同为 `payload.order.order_id`。修正仅
限测试字段，原失败日志保留，未据此修改金融代码。完整命令、精确提交及三运行时输出
另附在 `evidence/runs/numeric-contract/`。

这些本地测试不验证实际 USDT/USDC、反向合约、期权、PM、外部托管、跨片或复制，亦不
等于批处理、长稳或吞吐验收。现有约束下未发现本复核范围的运行时阻断问题。
