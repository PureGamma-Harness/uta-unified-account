# 预占数学与行情解析缓存的独立验证

本组只验证两项默认关闭的本地优化：完整经济输入对应的预占数值，以及持久行情原文对应的不可变解析对象。不缓存接单、可用额度、账户风险、权限、行情时效或政策检查结果。所有账户、价格、成交与资金均为合成数据。本报告允许候选继续工程审查，**不批准生产、完整 PM、多节点、持续万笔或真实资金启用**。

## 独立预期与人工案例

`tests/test_kernel_reference.py` 的预期只使用 `Fraction`、整数与独立现金/费用分项，不调用生产 `_reserve`、`_reserve_reference`、`calculate_reserve`、`_fee`、`_rounded` 或风险计算器生成预期。少数测试调用 `_reserve` 的返回值仅作为被比较的实际值。另一条服务关闭缓存的路径同样必须与独立预期比较，不能仅以两个生产实现相等判定正确。

令 `r = 原数量 − 累计已成交数量`，全部按精确有理数计算：

- 开仓 IM：非只减仓单为 `|r| × max(mark,limit) × IM率`；只减仓为零。
- 不利执行损失：`max(0,r × (limit−mark))`。
- 未付费用：`ceil_币种最小单位((历史成交名义 + |r|×limit) × 费率) − 累计已付费用`。

预占是以上三项之和。预期的费用向上取整使用有理数的整数商与余数，不受 Decimal 上下文影响。不同订单各自占用，缓存只重用相同算术答案，不能合并金融预占。

在 mark=100、IM=10%、费率=0.04%、USD 精度=2 时，人工案例为：

| 数量/限价 | 只减仓 | 历史已成交 | 预占 USD |
| --- | --- | --- | ---: |
| +1 / 100 | 否 | 无 | 10.04 |
| +1 / 101 | 否 | 无 | 11.15 |
| −1 / 99 | 否 | 无 | 11.04 |
| −1 / 99 | 是 | 无 | 1.04 |
| 原 +1 / 100 | 否 | 已成交 .99、名义99、已付 .04 | .10 |

最后一例保留已付的累计取整余量，不能为剩余数量再次单独向上取整并重复预占一分钱。

## 执行记录与审查结论

验证起点为 `92086bd`。本地独立 worktree 按顺序应用实现提交 `ec56058`、市场模块 `4a0e9f` 及服务接线 `a4aae6c`，没有修改生产函数。Python 3.12.14 / SQLite 3.53.1 下完整 **17 tests，0 failures/errors/skips，0.638秒**。随后将896个生成案例中的未成交与全部成交边界显式固定，避免仅靠随机抽中；同样17项再次全过，0.669秒。

开发中首次仅有两个缓存模块而服务尚未接线时，6个模块测试通过、9个服务测试因缺少 `market_cache_size` 参数而无法执行；这些未执行结果没有算作通过。接线后一次回归发现本测试对精度不兼容的异常类型预期过晚：既有 `DurableLedger` 在服务政策检查前抛出 `LedgerError`。测试现核对该原有明确拒绝，未改金融预期或生产行为。随后完整17项均执行通过。未发现已确认的数值差异、预占重复使用或缓存绕过门禁；没有为了通过而跳过失败案例。

本次是有界功能与故障回归，不证明任意组合的数学正确性、定点内核性能、硬件掉电耐久性、长期公平性、内存RSS绝对上界、复制/fencing、外部撮合/托管或完整PM。缓存清空和淘汰只影响性能；软件退回关闭缓存前仍须排空在途请求、保留原业务ID并对账，不能恢复旧账本来抹去已确认交易。最终集成提交的全量测试、安装矩阵、性能原始数据与回滚步骤由集成记录归档。生产与持续10,000/s门槛仍为 **BLOCKED**。

## 预占版本性质分支的只读审查

仅检查了 `92086bd..origin/test/reservation-version-property` 的5个增量提交：4个文件、119行，未整合整条分支。`VersionChecked` 以实际 `pending→held` 转换为条件，检查前状态的 `seen[o]=version`；它没有用本身包含版本guard的 `Commit(o)` 作前件，因此删除guard后不会获得空泛通过。该性质补足“容量仍足够，所以余额不变量仍过，但使用了过期版本”的检测。

新增 bridge 将独立有限模型的可达转换重放到内存 `ReservationBook`，并要求版本拒绝不改变状态；另有删除版本guard的反例。它可作为**单独的内存参考回归**引入，建议按这4文件的小补丁独立审查并归档TLC正、负控制输出。分支说明的2628状态/3873转换及TLC执行来自该分支记录，本组此次只读审查，没有冒称重新执行TLC。

`ExchangeService` 不暴露客户端 expected-version，其依据是当前 `BEGIN IMMEDIATE` 中的权威状态。本组17项测试中的真实服务案例及既有独立预占/故障测试构成这一路径的证据，不能用内存模型替代。该分支没有证明实现/模型任意规模等价、重启持久性、多进程fencing或生产批准；本轮未直接吞入其生产或测试文件。
